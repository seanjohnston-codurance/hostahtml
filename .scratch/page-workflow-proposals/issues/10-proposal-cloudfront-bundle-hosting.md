# 10 — Proposal: CloudFront-hosted bundle pages

Status: needs-triage

Suggested model: **Human** — this changes the share-page serving model and needs security/infra review before implementation.

## Parent

[PRD](../PRD.md) — Page workflow proposals

## What to build

Decide how HostaHTML should migrate bundle reads from Lambda-served `/t/{token}/...` paths to static bundle hosting through CloudFront. The proposal should keep `/t/{token}` as the stable user-facing share URL while evaluating a runtime path such as `/b/{bundleId}/...` for authorized static asset loading.

## Acceptance criteria

- [ ] Desired CloudFront URL shape is documented, including whether `/b/{bundleId}/...` is visible to users after authorization.
- [ ] Authorization model is chosen: CloudFront signed cookies, signed URLs, Lambda@Edge/CloudFront Functions, API Gateway origin, or another approach.
- [ ] Private S3 origin access model is documented, including how uploaded bundle objects remain non-public.
- [ ] Token expiry, revocation, and 7-day lifecycle behaviour remain aligned with ADR-0003 and ADR-0005.
- [ ] Cache behaviour is documented for HTML, assets, expired shares, revoked shares, and private responses.
- [ ] Migration path from Lambda-served V1 bundles is documented without breaking existing `/t/{token}` links.
- [ ] Infra and implementation follow-up tickets are split into independently verifiable slices.
