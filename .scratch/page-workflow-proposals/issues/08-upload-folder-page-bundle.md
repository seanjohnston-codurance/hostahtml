# 08 — Upload a page bundle from a folder

Status: needs-triage

Suggested model: **Human first, then AFK** — browser folder APIs are uneven enough that the interaction model should be confirmed before implementation.

Type: **Implementation candidate**

## Parent

[PRD](../PRD.md) — Page workflow proposals

## What to build

Let an authenticated user upload a page bundle by providing a local folder, ideally through drag and drop, so they do not need to create a `.zip` manually. The uploaded folder should use the same bundle validation, storage, and serving model as zipped bundle uploads.

## Acceptance criteria

- [ ] User can drag a folder containing a root `index.html` onto the upload area.
- [ ] Folder contents preserve relative paths when stored as a bundle.
- [ ] The folder upload path rejects the same unsafe paths, missing `index.html`, size-limit, and file-count cases as zip upload.
- [ ] If browser support requires a fallback, the UI explains when folder upload is unavailable and points users to zip upload.
- [ ] Existing `.html` and `.zip` upload behaviour remains supported.
- [ ] Tests cover a successful folder upload and one rejected invalid folder.
